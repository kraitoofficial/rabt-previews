Security Architecture Role-Based Access Control

Roles & Permission Matrix

Detailed breakdown of Rabt's 4-tier RBAC system, endpoint authorizations, and access privileges.

The 4 Role Tiers

Super Admin

Unrestricted platform owner. Full access to Organization Settings, SMTP configuration, white-label branding, all user management, audit logs, and all workspace modules.

Admin

Operational manager. Access to the Admin Dashboard, Users list (managing Staff & User accounts), system audit logs, and day-to-day operations across all workspace modules (Create, Read, Update). Record deletion is restricted to Super Admin.

Staff

Standard team member. Full daily operations across Contact Directory, Leads Pipeline, Invoices, Inventory, Files, and PDF Tools. Restricted from all /admin/* routes.

User

Customer or external viewer. Access limited to personal profile (/profile), organization contact information (/contact), and public invoice verification.

Deletion Safeguards: Under lib/config/access-control.ts, individual and bulk DELETE operations across Contacts, Leads, Invoices, Inventory, Files, and User Accounts are strictly restricted to Super Admin. Admin and Staff tiers have Create, Read, and Update (CRU) permissions to prevent catastrophic data loss.

Security Enforcement Architecture

Security in Rabt follows the fail-secure defense-in-depth principle:

  • Next.js Proxy Filter (proxy.ts): Blocks unauthorized roles before server components or routes even begin rendering.
  • API Access Control (lib/config/access-control.ts): Enforces strict method-level ACLs (GET, POST, PUT, DELETE) on every API endpoint.
  • Postgres Row Level Security (RLS): Directly at the database layer in Supabase, preventing data leakage even if API layers were bypassed.
