Deployment Guide v3.0.0

Installation & Setup Guide

Step-by-step instructions for deploying Rabt v3.0.0 on Vercel, Docker, or Linux VPS with Supabase.

Supabase Backend: Rabt v3.0.0 uses Supabase for Authentication, PostgreSQL database, and Storage. No MongoDB server or third-party file host is required.

System Requirements

Requirement Minimum Specification Recommended
Runtime Node.js 20.x or Bun 1.4+ Bun 1.4+ (Default in repository)
Database & Auth Supabase Cloud (Free/Pro) or Local Supabase Supabase Cloud Managed Postgres 15+
Memory (RAM) 2 GB RAM 4 GB RAM (Ensures fast Puppeteer PDF rendering)
Disk Space 10 GB Free Storage 20 GB+ for Docker images and caching

Quick Start Walkthrough

1. Clone Repository & Install Dependencies

Clone the Rabt repository and install node modules using Bun or npm:

git clone https://github.com/your-org/rabt-supabase.git
cd rabt-supabase

# Install using bun (preferred)
bun install

# Or using npm
npm install

2. Configure Supabase

Create a project at supabase.com or initialize local CLI:

# Run database migrations to provision tables, RLS policies, and RPCs
npx supabase db reset

Navigate to Project Settings → API in your Supabase Dashboard to retrieve:

  • NEXT_PUBLIC_SUPABASE_URL
  • NEXT_PUBLIC_SUPABASE_ANON_KEY
  • SUPABASE_SERVICE_ROLE_KEY
Storage Buckets: The migrations automatically provision the four required storage buckets: branding, files, invoices, and pdf-jobs with strict role-based policies.

3. Configure Environment Variables

Copy .env.example to .env.local and fill in your values:

# Supabase Configuration
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

# Application Configuration
NEXT_PUBLIC_APP_URL=https://yourdomain.com
NODE_ENV=production

# Initial Super Admin Email (Crucial for first sign in)
DB_ADMIN_EMAIL=admin@yourcompany.com

# SMTP Email Configuration (For Invoice emails & Payment reminders)
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=your-email@gmail.com
SMTP_PASSWORD=your-app-password
SMTP_FROM="Your Company "
SMTP_SECURE=false

# Security & Background Cron
CORS_ORIGINS=https://yourdomain.com
CRON_SECRET=generate-a-strong-random-token-here

# Database Maintenance (auto-prune old logs to stay under 500 MB DB limit)
LOG_RETENTION_DAYS=90

4. First Sign-In & Super Admin Promotion

Start the local development server or visit your deployed domain:

bun run dev
# App is available at http://localhost:3000

Sign up via the app using your email address. By security design, all new sign-ups default to the User role. Promote your account to Super Admin via the Supabase Dashboard SQL Editor: 

UPDATE public.profiles
SET role = 'Super Admin', is_verified = true
WHERE email = 'admin@yourcompany.com';

Once executed, refresh or sign in to immediately access User Management, System Logs, and Organization Settings.

Deployment Options

Option A: Vercel (Recommended Serverless)

Rabt is optimized for Vercel deployment with serverless routing and edge asset caching:

# Install Vercel CLI
npm i -g vercel

# Link and deploy
vercel

# Add all environment variables in Vercel Project Settings → Environment Variables
# Deploy to production
vercel --prod

Option B: Docker & Docker Compose

For independent self-hosting on your VPS using the included production Dockerfile:

# Start containers in detached mode
docker compose up -d --build

# View runtime logs
docker compose logs -f

Option C: PM2 on Ubuntu / Debian VPS

Deploy directly using the included ecosystem.config.js:

# Build standalone Next.js package
bun run build

# Start using PM2 process manager
pm2 start ecosystem.config.js
pm2 save
pm2 startup

Automated Payment Reminders (Cron Setup)

Rabt provides a unified cron endpoint at /api/cron that checks for invoices nearing or past their due dates and sends friendly email reminders to clients.

Authenticate requests using the Bearer token matching your CRON_SECRET:

Linux Crontab (Runs daily at 6:00 AM UTC)

0 6 * * * curl -X GET "https://yourdomain.com/api/cron" -H "Authorization: Bearer YOUR_CRON_SECRET"

Vercel Cron (Configured in vercel.json)

{
  "crons": [
    {
      "path": "/api/cron",
      "schedule": "0 6 * * *"
    }
  ]
}
